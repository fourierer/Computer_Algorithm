# 134.加油站 解题思路

## 问题分析

关键洞察：
- 若 `sum(gas) < sum(cost)`，油量总和不够消耗，一定无解
- 若 `sum(gas) >= sum(cost)`，**一定有唯一解**
- 从站点 i 出发，若到站点 j 时油量不足（`tank < 0`），则 i 到 j 之间的任何站点都不可能作为起点！因为中间任何一站出发的油量都会更少

## 解法：贪心一次遍历（推荐）

### 思路

1. 如果总油量 < 总消耗，直接返回 -1
2. 否则必定有唯一解。从站点 0 开始尝试，累加 `gas[i] - cost[i]` 到 `tank`
3. 若 `tank < 0`，说明从当前起点出发无法到达 i+1，起点跳到 `i+1`，`tank` 清零
4. 遍历结束后，`start` 就是答案

为什么正确？因为当 `tank < 0` 时，起点到 i 之间的所有站点都不可行（它们出发时油量只会更少），所以可以直接跳到 `i+1`。

### 错误思路警示

**❌ 错误想法**：总和 >= 0 时，从净收益最大的站出发即可。

**反例**：`gas = [5,8,2,8]`，`cost = [6,5,6,6]`
- 净收益 = [-1, 3, -4, 2]，总和 = 0 >= 0
- max(净收益) = 3 在 index=1，但从 index=1 出发：tank = 3 → 3-4 = -1 ❌ 失败
- 正确答案是 index=3：tank = 2 → 2-1 = 1 → 1+3 = 4 → 4-4 = 0 ✅ 成功

原因：局部最大净收益不保证全程不中断，贪心应基于"断点跳过"而非"最大净收益"。

### 算法步骤

1. 若 `sum(gas) < sum(cost)`，返回 -1
2. `start = 0`，`tank = 0`
3. 遍历 i 从 0 到 n-1：
   - `tank += gas[i] - cost[i]`
   - 若 `tank < 0`：`start = i + 1`，`tank = 0`
4. 返回 `start`

### 复杂度分析

- 时间复杂度：O(n)
- 空间复杂度：O(1)
