# 146.LRU缓存 解题思路

## 问题分析

LRU（Least Recently Used）缓存需要支持两个核心操作：
- `get(key)`：查找并返回缓存中的值，同时将该键值对标记为"最近使用"
- `put(key, value)`：插入或更新键值对，超容量时淘汰"最久未使用"的键值对

**关键约束：** 两个操作都必须在 O(1) 时间复杂度内完成。

**关键洞察：** 要实现 O(1) 的查找 + O(1) 的插入/删除，需要结合两种数据结构：
- **哈希表**：O(1) 查找 key 对应的节点
- **双向链表**：O(1) 在头部/尾部插入和删除节点

## 解法一：哈希表 + 双向链表（推荐）

### 思路

维护一个双向链表，链表头部（dummy_head 之后）表示最近使用的节点，链表尾部（dummy_tail 之前）表示最久未使用的节点。同时维护一个哈希表，key 映射到链表中的节点。

- **get**：哈希表查找 key → 将节点移到链表头部 → 返回值
- **put**：
  - key 已存在：更新值，移到链表头部
  - key 不存在：创建新节点，插入链表头部，加入哈希表；若超容量，删除链表尾部节点并从哈希表中移除

使用哑节点（dummy_head / dummy_tail）简化边界处理。

### 算法步骤

1. 初始化：创建 dummy_head 和 dummy_tail 并互连，初始化空哈希表和容量
2. `_add_to_head(node)`：将节点插入到 dummy_head 之后
3. `_remove_node(node)`：从链表中摘除节点（修改前后指针）
4. `_move_to_head(node)`：先摘除，再插入头部
5. `_pop_tail()`：摘除 dummy_tail 前面的节点并返回
6. `get(key)`：查哈希表 → 命中则 `_move_to_head` → 返回 val 或 -1
7. `put(key, value)`：查哈希表 → 命中则更新值 + `_move_to_head` → 未命中则新建 + `_add_to_head` → 超容量则 `_pop_tail` 并从哈希表删除

### 复杂度分析

- 时间复杂度：O(1)，get 和 put 均为常数时间
- 空间复杂度：O(capacity)，哈希表和双向链表各存储 capacity 个元素

## 解法二：Python OrderedDict（简洁写法）

### 思路

Python 的 `collections.OrderedDict` 内部实现就是哈希表 + 双向链表，天然支持 LRU 语义：
- `move_to_end(key)` → 移到最近使用端
- `popitem(last=False)` → 弹出最久未使用的元素

### 复杂度分析

- 时间复杂度：O(1)
- 空间复杂度：O(capacity)

## 解法对比

| 解法 | 时间复杂度 | 空间复杂度 | 说明 |
|------|-----------|-----------|------|
| 哈希表 + 双向链表 | O(1) | O(capacity) | 通用解法，面试推荐手写 |
| OrderedDict | O(1) | O(capacity) | Python 简洁写法，但面试中通常要求手写 |
