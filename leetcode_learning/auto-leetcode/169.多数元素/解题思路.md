# 169.多数元素 解题思路

## 问题分析

关键洞察：
- 多数元素出现次数 **严格大于** `n/2`，这意味着多数元素的数量超过所有其他元素之和
- 因此，若将多数元素记为 +1，其他元素记为 -1，总和一定为正
- 这也正是 Boyer-Moore 投票算法的核心思想

## 解法一：哈希计数

### 思路

遍历数组，用哈希表统计每个元素的出现次数，出现次数超过 `n/2` 的即为答案。

### 复杂度分析

- 时间复杂度：O(n)
- 空间复杂度：O(n)

## 解法二：排序取中位

### 思路

多数元素数量超过 `n/2`，排序后它一定占据正中间的位置（下标 `n//2`）。

### 复杂度分析

- 时间复杂度：O(n log n)
- 空间复杂度：O(1)（取决于排序算法）

## 解法三：Boyer-Moore 投票算法（推荐）

### 思路

将多数元素视为"候选人"，其他元素视为"反对票"。每遇到一个与候选人相同的元素，票数 +1；不同则 -1。票数归零时更换候选人。

由于多数元素数量超过一半，最终一定会剩下来。

### 算法步骤

1. 初始化 `candidate` 为任意值，`count = 0`
2. 遍历 `nums`：
   - 若 `count == 0`：更换候选人为当前元素，`count = 1`
   - 若 `nums[i] == candidate`：`count += 1`
   - 否则：`count -= 1`
3. 返回 `candidate`

### 复杂度分析

- 时间复杂度：O(n)
- 空间复杂度：O(1)

## 解法对比

| 解法 | 时间复杂度 | 空间复杂度 | 说明 |
|------|-----------|-----------|------|
| 哈希计数 | O(n) | O(n) | 直观，但需要额外空间 |
| 排序取中位 | O(n log n) | O(1) | 简洁，但时间略慢 |
| Boyer-Moore 投票 | O(n) | O(1) | 最优解，满足进阶要求 |
