# 215.数组中的第K个最大元素 解题思路

## 问题分析

关键洞察：
- 第 k 个最大元素 = 排序后索引为 `n - k` 的元素（升序排列时）
- 不需要完全排序，只需找到第 `n - k` 小的元素
- 快速选择算法（QuickSelect）基于快排的分区思想，平均 O(n)

## 解法一：堆（小顶堆）

### 思路

维护一个大小为 k 的小顶堆，遍历数组时：
- 堆未满 k 个，直接入堆
- 堆已满 k 个且当前元素 > 堆顶，弹出堆顶再入堆

遍历结束后，堆顶就是第 k 大的元素。

### 复杂度分析

- 时间复杂度：O(n log k)
- 空间复杂度：O(k)

## 解法二：快速选择（推荐）

### 思路

基于快排的 partition 操作：
1. 随机选取基准值（pivot），将数组分为 `< pivot` 和 `> pivot` 两部分
2. 目标索引 `target = n - k`（升序排列时第 k 大的位置）
3. 若 pivot 落在 `target` 位置，直接返回；否则只在目标所在的一侧递归

为什么平均 O(n)：每轮分区后只递归一侧，n + n/2 + n/4 + ... ≈ 2n

### 算法步骤

1. 设 `target = n - k`
2. 在 `[left, right]` 范围内随机选 pivot 并分区
3. partition 返回 pivot 的最终位置 `p`
   - 若 `p == target`，返回 `nums[p]`
   - 若 `p < target`，在 `[p+1, right]` 继续查找
   - 若 `p > target`，在 `[left, p-1]` 继续查找

### 复杂度分析

- 时间复杂度：平均 O(n)，最坏 O(n²)（随机化后几乎不可能）
- 空间复杂度：O(1)（原地分区）

### 复杂度推导

每轮分区后只递归一侧。第 1 轮比较 n 次，第 2 轮比较约 n/2 次，第 3 轮约 n/4 次……

总比较次数 = n + n/2 + n/4 + ... ≈ 2n，因此平均时间复杂度为 O(n)。

## 解法对比

| 解法 | 时间复杂度 | 空间复杂度 | 说明 |
|------|-----------|-----------|------|
| 小顶堆 | O(n log k) | O(k) | 简单直观，适合数据流场景 |
| 快速选择 | 平均 O(n) | O(1) | 最优解，原地分区无需额外空间 |
