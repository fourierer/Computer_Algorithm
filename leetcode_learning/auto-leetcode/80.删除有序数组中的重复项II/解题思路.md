# 80.删除有序数组中的重复项II 解题思路

## 问题分析

关键洞察：
- 数组有序，重复元素相邻，便于判断是否超过两次
- 这是第 26 题的推广：第 26 题允许每个元素出现 1 次，本题允许出现最多 2 次
- 可以用类似的快慢指针思路，但需要调整判断条件

## 解法一：通用快慢指针（推荐）

### 思路

第 26 题中，慢指针 `slow` 之前的元素已经满足条件，判断条件是 `nums[fast] != nums[slow-1]`（与前一个已保留元素不同才写入）。

本题允许每个元素出现最多两次，因此判断条件改为：`nums[fast] != nums[slow-2]`。

- 当 `slow < 2` 时，前两个元素一定可以保留（每个元素最多出现两次）
- 当 `slow >= 2` 时，只有 `nums[fast] != nums[slow-2]` 才写入，这保证了同一个元素最多被写入两次

**直觉理解**：`nums[slow-2]` 是当前写入位置往前数第二个元素。如果 `nums[fast] == nums[slow-2]`，说明 `nums[slow-2]`、`nums[slow-1]`、`nums[fast]` 三个相同，写入 `nums[fast]` 就会超过两次，所以跳过。

### 算法步骤

1. 若 `nums` 长度 ≤ 2，直接返回长度
2. `slow = 2`（前两个元素直接保留）
3. `fast` 从 2 遍历到末尾：
   - 若 `nums[fast] != nums[slow-2]`：`nums[slow] = nums[fast]`，`slow += 1`
4. 返回 `slow`

### 复杂度分析

- 时间复杂度：O(n)
- 空间复杂度：O(1)

## 解法二：计数快慢指针

### 思路

显式维护一个计数器，记录当前元素已出现的次数，超过 2 次则跳过。

### 算法步骤

1. 若 `nums` 长度 ≤ 2，直接返回长度
2. `slow = 1`，`count = 1`（`nums[0]` 已出现 1 次）
3. `fast` 从 1 遍历到末尾：
   - 若 `nums[fast] == nums[slow-1]`：`count += 1`
   - 否则：`count = 1`
   - 若 `count <= 2`：`nums[slow] = nums[fast]`，`slow += 1`
4. 返回 `slow`

### 复杂度分析

- 时间复杂度：O(n)
- 空间复杂度：O(1)

## 推广：允许每个元素最多出现 K 次

### 核心规律

观察第 26 题（K=1）和本题（K=2）的判断条件：

| 问题 | K | 判断条件 | 含义 |
|------|---|---------|------|
| 第26题 | 1 | `nums[fast] != nums[slow]` | 与末尾元素不同 |
| 第80题 | 2 | `nums[fast] != nums[slow-1]` | 与倒数第2个保留元素不同 |
| 通用 | K | `nums[fast] != nums[slow-K+1]` | 与倒数第K个保留元素不同 |

**直觉理解**：`slow` 之前是已确认保留的部分。如果 `nums[fast] == nums[slow-K+1]`，说明从 `slow-K+1` 到 `slow` 这 K 个位置都是同一个元素，再写入就会超过 K 次。

### 算法步骤

1. 若 `nums` 长度 ≤ K，直接返回长度
2. `slow = K - 1`（前 K 个元素直接保留）
3. `fast` 从 K 遍历到末尾：
   - 若 `nums[fast] != nums[slow-K+1]`：`slow += 1`，`nums[slow] = nums[fast]`
4. 返回 `slow + 1`

### 复杂度分析

- 时间复杂度：O(n)
- 空间复杂度：O(1)

## 解法对比

| 解法 | 时间复杂度 | 空间复杂度 | 说明 |
|------|-----------|-----------|------|
| 通用 K 次快慢指针 | O(n) | O(1) | K=1 退化为第26题，K=2 即本题 |
| 计数快慢指针 | O(n) | O(1) | 逻辑清晰直观，需要额外计数变量，不易推广到 K |
