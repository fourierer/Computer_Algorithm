# 82. 删除排序链表中的重复元素 II - 解题思路

## 问题分析

已排序链表中，重复元素必然相邻。本题的关键区别在于：**所有重复的节点都要删除**，而不是保留一个。

核心难点：头节点本身可能是重复节点，删除后需要返回新的头节点。

## 解法：虚拟头节点 + 一次遍历

### 思路

1. 创建虚拟头节点 `dummy`，其 `next` 指向 `head`，统一处理头节点被删除的情况
2. 用指针 `cur` 从 `dummy` 开始遍历，检查 `cur.next` 和 `cur.next.next` 的值是否相等
3. 若相等，记录该重复值 `x`，将 `cur.next` 不断跳过所有值为 `x` 的节点
4. 若不相等，`cur` 正常后移一位
5. 返回 `dummy.next`

### 算法步骤（伪代码）

```
dummy = ListNode(0, head)
cur = dummy
while cur.next != null and cur.next.next != null:
    if cur.next.val == cur.next.next.val:
        x = cur.next.val
        while cur.next != null and cur.next.val == x:
            cur.next = cur.next.next
    else:
        cur = cur.next
return dummy.next
```

### 复杂度分析

- **时间复杂度**：O(n)，每个节点最多被访问一次
- **空间复杂度**：O(1)，只使用常数额外空间

## 解法对比

| 解法 | 时间复杂度 | 空间复杂度 | 说明 |
|------|-----------|-----------|------|
| 虚拟头节点 + 一次遍历 | O(n) | O(1) | 推荐，简洁高效 |
| 递归 | O(n) | O(n) | 思路清晰但空间开销大 |
| 哈希表计数 | O(n) | O(n) | 不利用已排序特性，空间浪费 |
